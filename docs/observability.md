# Enterprise Observability & Tracing Architecture

InsightStream AI implements enterprise-level observability and tracing using **.NET Aspire** and **OpenTelemetry**. 

During local execution, the telemetry pipeline collects detailed structural spans for execution flows (including Semantic Kernel operations, agent handoff turns, database interactions, and HTTP requests) and exports them directly to the .NET Aspire Dashboard.

---

## 1. Observability Pipeline Design

The observability structure is built across three primary components:

1.  **`InsightStreamAI.ServiceDefaults` (Shared Project):**
    *   Integrates the OpenTelemetry SDK with standard trace/metric providers.
    *   Registers default diagnostic instrumentation for ASP.NET Core request handling, outbound HttpClient transactions, and runtime resource utilization metrics.
    *   Configures the OpenTelemetry Protocol (OTLP) exporter, directing telemetry to the Aspire Dashboard endpoints.
2.  **`InsightStreamAI.Infrastructure` (Telemetry Provider):**
    *   Enables detailed instrumentation for **Semantic Kernel** via experimental app switches:
        *   `Microsoft.SemanticKernel.Experimental.GenAI.EnableOTelDiagnostics`: Activates core tracking for LLM actions and pipeline processes.
        *   `Microsoft.SemanticKernel.Experimental.GenAI.EnableOTelDiagnosticsSensitive`: Enables prompt contents, completion answers, and key-value model arguments inside traces (strictly scoped for local development/debugging).
    *   Subscribes the trace engine to `Microsoft.SemanticKernel*` activity sources.
    *   Subscribes the metrics engine to `Microsoft.SemanticKernel*` meters.
3.  **`InsightStreamAI.AppHost` (Orchestrator Host):**
    *   Spins up the shared **Aspire Dashboard** environment.
    *   Handles local app configuration and configuration injection.

## 2. Telemetry Output & Spans Collected

By subscribing to Semantic Kernel activity sources, the following telemetry details are logged automatically:

### Tracing Details (Spans)
*   **LLM Model Actions:** Tracks each call to OpenAI/LM Studio, capturing:
    *   `gen_ai.system`: The model identifier or system setting.
    *   `gen_ai.request.model`: Target model ID.
    *   `gen_ai.response.model`: Model that generated the output.
    *   `gen_ai.prompt`: The exact prompt context sent to the model (due to sensitive telemetry option).
    *   `gen_ai.completion`: The text generated by the model.
*   **Semantic Kernel Functions (Tool Calls):**
    *   Logs execution start and duration for native plugins:
        *   `TimePlugin.GetCurrentTime`
        *   `WebSearchPlugin.SearchAsync`
        *   `DocumentQueryPlugin.QueryDocumentsAsync`
    *   Captures arguments passed to functions and returned values.
*   **Agent Flow Coordination:**
    *   Underlying chat completions requested by individual `ChatCompletionAgent` nodes (e.g., `RouterAgent`, `DocumentResearchAgent`, `WorkspaceAutomationAgent`) are recorded in the order they execute, establishing visual parent-child relationship chains in the trace waterfall.

### Metrics Collected (Meters)
*   **Token Counts:**
    *   `semantic_kernel.connectors.openai.tokens.prompt`: Count of prompt tokens.
    *   `semantic_kernel.connectors.openai.tokens.completion`: Count of completion tokens.
    *   `semantic_kernel.connectors.openai.tokens.total`: Combined token counts per execution.
*   **Performance Latency:**
    *   `semantic_kernel.connectors.openai.duration`: Histogram of model request durations.

## 3. Distributed Configuration & Secrets Architecture

In addition to collecting telemetry, the **AppHost orchestrator** serves as the central control plane for all application settings and secrets:

### Database Connection Secrets Routing
The database connection string is stored securely in the AppHost User Secrets (`ConnectionStrings:DefaultConnection`) and passed dynamically to the Blazor application via a Connection String Resource.
*   **AppHost Definition:** `builder.AddConnectionString("DefaultConnection", ReferenceExpression.Create($"{connectionString}"))`
*   **Blazor Consumption:** `builder.Configuration.GetConnectionString("DefaultConnection")`

### Secure AI Settings & Database Secrets (User Secrets)
Sensitive values (like OpenAI-compatible API keys, model IDs, local API URLs, and database connection strings) are stored securely in the AppHost project's **User Secrets manager** and passed to target applications as environment variables at runtime. This completely eliminates plaintext configuration and hardcoded parameters.

To set these values locally, run the following commands under `src/InsightStreamAI.AppHost`:
```powershell
# Initialize secrets
dotnet user-secrets init

# Map database connection string, credentials and model endpoints
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Data Source=insightstream.db"
dotnet user-secrets set "AISettings:ApiKey" "sk-lm-NXDn8jQx:lqsApi2V5bC2mIabHcBR"
dotnet user-secrets set "AISettings:ChatModelId" "qwen/qwen3.5-9b"
dotnet user-secrets set "AISettings:EmbeddingModelId" "text-embedding-mxbai-embed-large-v1"
dotnet user-secrets set "AISettings:LocalEndpoint" "http://localhost:1234/v1"
```

## 4. How to View Traces

1.  Start the solution via the AppHost:
    ```powershell
    dotnet run --project src/InsightStreamAI.AppHost
    ```
2.  Open the **Aspire Dashboard** link shown in the terminal (usually `https://localhost:17123`).
3.  In the left sidebar, click on **Traces**.
4.  Interact with the Blazor Chat UI (e.g., submit a message).
5.  Click on the newly generated trace in the Aspire Dashboard to inspect the end-to-end waterfall layout showing router handoffs, database reads, similarity searches, and final LLM generation steps.
